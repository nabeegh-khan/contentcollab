# tests

Cross-service checks that do not belong to one service: the restart test (data survives deleting the postgres pod), the scale test (requests keep succeeding while the api Deployment scales), and the end-to-end smoke run against a deployed stack. Unit and route tests live next to their service (`api/tests/`).

## Practices that apply here

From [`docs/PRACTICES.md`](../docs/PRACTICES.md) (generated by `scripts/sync-practices.py`; edit the source, not this list). Paste this section into whatever tool you write code with.

| ID | Practice | Here |
|---|---|---|
| DB-3 | Volumes are not backups and not shared storage | Nightly `pg_dump` to Spaces; files never written to a pod's disk |
| API-7 | Handle shutdown signals: stop accepting requests, finish in-flight ones, close the database pool | Rolling updates and autoscaling drop no requests |
| API-8 | Health endpoint that the platform checks; readiness separate from liveness | `/health` for liveness; readiness only once Postgres and Redis answer |
| TST-1 | Export the app without starting the server; tests drive it on a free port against a reset test database, serially | Jest and Supertest with a Postgres service container in CI |
| TST-2 | Write tests beyond the samples; assert exact codes, messages and shapes | Every route has a test for the happy path and each error |
| TST-3 | Probe what the tests skip with a curl script and read the bodies | `scripts/smoke.sh` run before every demo |
| TST-4 | Verify persistence by restarting the stack | The restart test is a rehearsed demo step |
| TST-5 | Tests run in CI on every pull request; `main` is deployable | GitHub Actions |
