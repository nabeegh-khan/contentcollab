# scripts

Repeatable operations as scripts, so nothing important lives in dashboard clicks. Every script exits early if a required environment variable is missing.

| Script | What it does | Needs |
|---|---|---|
| `cluster-up.sh` | Creates the DOKS cluster, installs the Gateway controller, cert-manager and (optionally) the Datadog agent, applies the Secret and the doks overlay | `doctl`, `kubectl`, `helm`, `LETSENCRYPT_EMAIL`; `DATADOG_API_KEY` optional |
| `cluster-down.sh` | Deletes the cluster, its load balancer and volumes after grading | `doctl` (authenticated with `doctl auth init`) |
| `alerts.sh` | DigitalOcean alert policies on the nodes: CPU, memory, disk above 80% for five minutes, one set per cluster (a rebuilt cluster gets new ones; delete the old with `doctl monitoring alert delete`) | `doctl` (authenticated), the cluster up, `ALERT_EMAIL` (the account's email or a verified team member's) |
| `smoke.sh` | The curl checks run before every demo: `/health` with both dependencies ok, `/metrics` present (through a port-forward only; the Gateway does not route it), an unknown `/api` route is the API's 404. Once the `SMOKE_URL` variable is set, `deploy.yml` checks `/health` after each rollout itself | `BASE` (default `http://localhost:3000`); `METRICS_BASE` when `BASE` is the deployed URL |
| `loadtest.mjs` | Stepped load against the deployed API for the autoscaling test (#69): sent and served req/s, p50 and p95 latency of successful requests, errors and ready API replicas per step, or a rolling restart under load with `ROLLOUT=1`, which exits 1 if the rollout fails or does not finish. Results and column meanings in `docs/loadtest/`. Refuses to start while the HPA cannot read CPU; warns and continues when no cluster is reachable | Node, a reachable API |
| `rollout-no-drop.sh` | Restarts (or with `ACTION=undo` rolls back) the api Deployment under a steady k6 load run from a Job inside the cluster, and exits 1 if any request was not 2xx. Needs a new revision and the load still running when the rollout ends. Targets the API Service's `/metrics`, since `/health` can fail under load with no rollout (ARCHITECTURE D14). Prints the context, the nodes (count, size, allocatable memory) and the node autoscaler's bounds as the cluster reports them, and refuses to start when any node it can read has less free memory than the run can add (the k6 pod's 512 MiB limit plus `maxSurge` times the memory limit of the container named `api`, read from the Deployment, unless `MIN_NODE_FREE_MIB` is set; for `ACTION=undo` that is the current template, so set it if the previous revision had a larger limit); a node whose memory cannot be read is named as not checked, and the run stops unless `ALLOW_UNCHECKED_MEMORY=1`. Tested through a stub `kubectl` by `rollout-no-drop.test.mjs` | `kubectl`, a cluster with the api Deployment; `ACTION`, `RATE`, `DURATION`, `MIN_NODE_FREE_MIB`, `ALLOW_UNCHECKED_MEMORY` optional |
| `pv-retain.sh` | Sets the PersistentVolume behind `data-postgres-0` to `Retain`, so deleting the claim or the namespace keeps the volume (#104); prints the policy before and after, does nothing if it is already `Retain`. Not a backup, and `cluster-down.sh` (`--dangerous`) still deletes the volume | `kubectl`, `KUBE_CONTEXT`, a cluster |
| `restart-test.sh` | The restart test (#68): writes a marker row, then reads it back after the postgres pod is deleted, the API is restarted (read by an API pod), PostgreSQL is scaled to 0 and back, and with `DRAIN=1` (two Ready, schedulable nodes or more) its node is drained; a pass counts only if the pod was really replaced, and after events 1 and 3 the running API must answer `/health` ok again with no container restart. Leaves the `restart_test` table. PostgreSQL is down during events 1 and 3 (and moves node in 4); after about 15 s the API pods go unready, so the site serves nothing until it is back. A drain evicts every pod on the node except DaemonSet pods, in every namespace. Not during a demo | `kubectl`, `KUBE_CONTEXT`, a cluster |
| `metrics-server.sh` | Installs metrics-server, pinned, so the HPA can read CPU | `kubectl`, a cluster |
| `observability-up.sh` | Installs the observability stack of ARCHITECTURE D19 into the namespace `observability` (part a: Prometheus, kube-state-metrics, Grafana with its dashboard). Refuses a kubectl context other than `EXPECTED_CONTEXT` and fewer than two Ready nodes (prints the node-pool command; `ALLOW_ONE_NODE=1` overrides); creates the Grafana password once, never prints it; `DRY_RUN=1` changes nothing | `kubectl`, the cluster up |
| `observability-down.sh` | Removes the stack, its namespace and its cluster roles, and prints the command that lets the pool return to one node | `kubectl` |
| `cross-replica.mjs` | The cross-replica check for real-time (sprint item 5, ARCHITECTURE D12): opens Socket.IO clients through the public Gateway one at a time, attributes each to an API pod by the ESTABLISHED connections on port 3000 that appeared in it (`kubectl exec ... cat /proc/net/tcp`), until two pods each hold one, joins them to one version, posts a comment over REST and requires it to arrive on both; deletes the comment; writes `docs/evidence/<date and time>-cross-replica.txt`. Exit 0 on PASS, 1 on FAIL or a missing setting. A socket it cannot attribute is not counted; probes and gateway keep-alive connections can blur the count, so a run that never finds two pods says so instead of passing. Needs a document with a version the user has a share on (#116 or a seeded row). Logic tested by `cross-replica-lib.test.mjs`; the kubectl and socket wiring is not tested offline | `kubectl`, `npm ci` in `api/`, `EMAIL`, `PASSWORD`, `DOCUMENT_ID`, `VERSION_ID` With `DIRECT=1` the sockets are opened on two named pods through `kubectl port-forward` instead, so nothing is attributed by counting; use it, because the Gateway's short-lived HTTP connections can disturb the counts (first run, 21 Nov). |
| `hpa-ready.mjs` | Exits 1 with the reason while the HPA cannot read CPU | `kubectl`, a cluster |
| `error-rate.mjs` | The 5xx share per route from the API's JSON request log on standard input: `kubectl -n contentcollab logs -l app=api --since=5m --tail=-1 --prefix \| node scripts/error-rate.mjs` (`--tail=-1` is needed: with `-l`, kubectl returns only the last 10 lines of each pod otherwise). Exit 1 above `THRESHOLD` (default 0.02) for a route with at least `MIN_REQUESTS` (default 10), or any failing `/health` or `/metrics` (their successes are not logged); exit 2 when the input has no request lines, a request line cannot be read, a setting is bad, or the script fails. Aborted requests are shown in their own column (ARCHITECTURE D18; in the cluster since #112: D19) | Node |
| `memory-headroom.mjs` | Memory left on each node by requests and by use, and with the API at the autoscaler's maximum; `AGENT_MI=768` says whether an agent of that size fits, `CLUSTER_AGENT_MI` whether it can be placed. Exit 0 with the report; exit 2 when kubectl fails, a node has no `kubectl top` reading, no API pod is found in `NAMESPACE`, a memory quantity cannot be read, a size is not a plain number of MiB, `CLUSTER_AGENT_MI` is given without `AGENT_MI`, or the script fails. Read-only (ARCHITECTURE D18; in the cluster since #112: D19) | `kubectl`, a cluster |
| `ci-kubeconform.sh` | CI only: validates rendered manifests with kubeconform, strictly, at each version in the `KUBE_VERSION` list that `ci.yml` sets (1.36.0 and 1.37.0), with the CRD catalogue for the Gateway and ClusterIssuer | `kubeconform`, `KUBE_VERSION` |
| `ci-k8s-cloud.sh` | CI only: renders `k8s/doks/infra` and `k8s/doks/migrate-job.yaml` (`__IMAGE_TAG__` filled in) and validates them; skipped while they do not exist. Fails on any other placeholder | `kubectl`, `kubeconform`, `KUBE_VERSION` |
| `ci-migrate-check.sh` | CI only: runs the migrations up, `down 0`, up against the database the `PG*` variables name and fails on any error; skipped while `api/migrations` does not exist. Run from `api/` | `npm`, `PG*` variables |
| `sync-practices.py` | Copies the applicable rows of `docs/PRACTICES.md` into each folder README | Python |
| `meeting-actions.py` | Turns a meeting's Actions table into GitHub Issues | GitHub CLI |
| `do-project.sh` | The DigitalOcean project `ContentCollab`, found by exact name or created once (#53; steps in `k8s/README.md`) | `doctl` (authenticated) |
| `app-secret.sh` | Creates or updates the `app-secrets` Secret from the environment, the existing Secret, a prompt or generated values, over stdin and never as an argument; keeps `DB_PASSWORD` and `JWT_SECRET` once set; removes the plain-text annotation a client-side apply leaves; `RESTART=1` restarts api and worker | `kubectl`; `SPACES_KEY` and `SPACES_SECRET` in the environment or typed at a prompt |
| `spaces-verify.sh` | Proves a Spaces key can put, upload in parts, copy and delete, that an anonymous read is refused and, with `FOREIGN_BUCKET`, that the key is refused on another bucket; deletes what it wrote | AWS CLI v2, `curl`, `SPACES_KEY` and `SPACES_SECRET` |

`*.test.mjs` run in CI with `node --test scripts/*.test.mjs`. The tests of the shell scripts run them against stand-ins for kubectl, doctl, the AWS CLI and curl in `testdata/`, and refuse to run unless the stand-ins are the ones on PATH.

## Practices that apply here

From [`docs/PRACTICES.md`](../docs/PRACTICES.md) (generated by `scripts/sync-practices.py`; edit the source, not this list). Paste this section into whatever tool you write code with.

| ID | Practice | Here |
|---|---|---|
| INF-3 | Script cloud tasks through the CLI or API and stop early if a required variable is missing | Cluster setup, volume creation and backups live in `scripts/`, not in dashboard clicks; `cluster-up.sh` checks its tools, the doctl sign-in and every variable before it changes anything, and `DRY_RUN=1` prints the changes instead of making them (D13) |
| INF-7 | Destroy what you are not using; stopped machines and detached volumes still bill | Cluster deleted after grades; a budget line in the proposal |
| SEC-1 | Secrets in environment or a secret store, never in code or images; commit only `.env.example` | `.env` is ignored; Kubernetes Secrets in the cluster |
| DB-3 | Volumes are not backups and not shared storage | Nightly `pg_dump` to Spaces; files never written to a pod's disk |
| DB-12 | Delete persistent data only on purpose (`down -v`, volume delete) | Never against demo data |
| TST-3 | Probe what the tests skip with a curl script and read the bodies | `scripts/smoke.sh` run before every demo |
| TST-4 | Verify persistence by restarting the stack | The restart test is a rehearsed demo step |
